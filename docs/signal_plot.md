# 信号解析与绘图（Signal Plot）使用指南

面向**没有 Python 基础**的使用者：在图形界面里按协议把 CAN 报文字节拆解成命名信号
（如转速、力、温度…），并把这些信号自由组合到多路实时曲线图里观察。协议定义与绘图
布局都可保存为 JSON，复用、分享、版本管理都很方便。

> 该窗口**只接收并解析数据 + 绘图**，不做发送/编码。数据来自主窗口当前连接的设备。

## 文件结构与关系

信号解析与绘图作为一个独立特性，归入 `gui/signal_plot/` 子包（与硬件层 `gui/hw/` 同级）：

```
gui/
├── main_gui.py            # 主界面：连接收发；右下「信号解析与绘图」按钮打开本窗口
├── can_communicator.py    # 跨平台 CAN 收发后端
├── hw/                    # 硬件连接管理
└── signal_plot/           # 信号解析与绘图特性包
    ├── __init__.py        # 导出 SignalPlotWindow / CodecDatabase / MessageDef / SignalDef
    ├── codec.py           # 编解码引擎（纯 Python，无 Qt 依赖，可单独使用/测试）
    ├── window.py          # PySide6 + pyqtgraph 窗口 UI
    └── protocols/         # 协议定义与布局的 JSON 示例
        ├── force_torque_sensor.json
        └── force_torque_layout.json
```

数据流：`main_gui` 连接设备 → `CANCommunicator` 收到真实帧 → 主窗口在绘图窗口打开时
通过 `plot_frame_signal` 把帧流喂给 `SignalPlotWindow.on_frames()` → `codec` 按协议解码
→ 数值表与曲线图刷新。绘图窗口不单独连接硬件。

只需要编解码引擎、不想引入 GUI 依赖时，直接：
```python
from gui.signal_plot.codec import CodecDatabase
db = CodecDatabase.load_json("gui/signal_plot/protocols/force_torque_sensor.json")
values = db.decode_frame(can_id=0x0B, is_extended=False, data=frame_bytes)
```

## 打开窗口

1. 启动主界面：`python3 gui/main_gui.py`
2. 在「报文接收」区的控制行点击 **「信号解析与绘图」** 按钮。
3. 弹出独立窗口；可与主窗口并排摆放。再次点击按钮会把已打开的窗口前置，不会重复创建。

> 窗口**不依赖连接**也能打开，可离线编辑/保存协议定义。要看实时曲线则需先在主窗口连接设备。

## 选择数据源

窗口右侧控制栏的「**数据源**」用于决定画哪个来源的数据：

| 控件 | 作用 |
|---|---|
| **数据源 下拉** | 选「全部通道」或某个具体通道（如 `can0`、`can1`）。选项随收到的帧**自动出现**——某通道一旦有数据进来就加入下拉。选定后只解码/绘制该通道的帧。 |
| **只看接收(RX)** | 勾选后过滤掉工具自己发出去的 TX 回显帧，只显示真正从设备接收的帧。 |

- 只连了一个设备时，保持「全部通道」即可。
- 多通道上有**相同 CAN ID** 时，用通道下拉区分来源。
- 只收不发的传感器（如力/力矩传感器）建议勾选「只看接收」。
- 下拉里看不到目标通道：确认主窗口已连接该通道、且该通道有数据进来。

## 定义协议（可视化编辑器）

左侧「协议定义」区用树状结构展示 **报文 → 信号**。

**新建一条报文**：点「新建报文」，填写：

| 字段 | 说明 |
|---|---|
| 报文名称 | 任意名称，如 `FT_Sensor` |
| 仲裁 ID (Hex) | 十六进制，如 `123` 或 `18FF50E5` |
| 扩展帧 | 勾选=29 位扩展帧；不勾=11 位标准帧 |
| DLC 长度 | 数据字节数（CAN FD 可到 64） |

**给报文新建信号**：先在树里选中该报文，点「新建信号」，填写：

| 字段 | 说明 |
|---|---|
| 信号名称 | 如 `Fx`、`rpm` |
| 起始字节 | 从第几个字节开始（0 起算） |
| 起始位 (0-7) | 字节内起始位，LSB=0；整字节信号填 0 |
| 位长度 | 信号占多少位（浮点必须 32 或 64） |
| 字节序 | **大端 (Motorola)** 或 **小端 (Intel)** |
| 数据类型 | **整数** 或 **IEEE-754 浮点** |
| 有符号 | 整数时是否按补码有符号解释（浮点忽略此项） |
| 缩放系数 | 工程量 = 原始值 × 缩放 + 偏移；支持 `0.02`、`1/50`、`1e-6` 写法 |
| 偏移量 | 同上 |
| 单位 | 如 `N`、`NM`、`A`、`deg`（仅显示用） |

**位域语义**（起始位按字节内 LSB=0 计数）：
- **小端 (Intel)**：信号最低位在 (起始字节, 起始位)，向高位延伸。整字节时等价于
  `int.from_bytes(data[start:start+N], 'little')`。
- **大端 (Motorola)**：从起始字节起按大端读取，整字节时等价于
  `int.from_bytes(data[start:start+N], 'big')`。
- **IEEE-754 浮点**：必须字节对齐（起始位为 0）、位长 32（单精度）或 64（双精度），
  按所选字节序还原浮点值。

「编辑」「删除」对选中的报文或信号生效。

## 导入 / 导出协议

- **导出协议**：把当前所有报文/信号定义保存为 JSON。
- **导入协议**：从 JSON 载入（会替换当前定义并清空已有数据缓存）。

把团队约定好的协议 JSON 分享给同事，对方导入即可，无需写任何代码。

## 绘制曲线

右侧是可**自由增删**的曲线图区：

1. 点「**添加曲线图**」新增一个窗格。
2. 在窗格里点「**选择信号...**」，勾选该窗格要绘制的信号（可多选）；每行右侧有一个
   **颜色色块**，点击可为该曲线自定义颜色（不改则用默认配色）。
3. 实时曲线随接收数据滚动；左侧「实时信号值」表同时显示各信号最新值。

> 曲线颜色会随**绘图布局**一起保存，下次导入布局即恢复你设定的配色。

顶部控制：

| 控件 | 作用 |
|---|---|
| 暂停 / 继续 | 冻结/恢复采集与绘制 |
| 清空数据 | 清空所有缓存与曲线，时间轴归零 |
| 时间窗口(s) | X 轴显示的时间跨度 |
| 自动滚动 | 勾选时 X 轴跟随最新时刻；取消可自由平移/缩放查看历史 |
| 删除此图 | 移除该窗格 |

不同窗格可画不同信号组合，比如力 `Fx/Fy/Fz` 一张图、力矩 `Mx/My/Mz` 一张图。

---

## 导入 / 导出绘图布局

- **导出布局**：保存当前有哪些曲线图窗格、各画哪些信号、时间窗口与自动滚动设置。
- **导入布局**：按 JSON 重建窗格组合（先清空现有窗格）。

> 布局里引用的是「报文名.信号名」（如 `FT_Sensor.Fx`）。导入布局前请先导入对应协议，
> 否则信号名对不上、画不出曲线。

## 配置文件格式参考

### 协议定义 JSON

```jsonc
{
  "version": 1,
  "messages": [
    {
      "name": "FT_Sensor",        // 报文名
      "can_id": 11,                // 仲裁 ID（十进制；11 = 0x0B）
      "is_extended": false,        // 是否扩展帧
      "dlc": 24,                   // 数据字节数
      "signals": [
        {
          "name": "Fx",            // 信号名
          "start_byte": 0,         // 起始字节
          "start_bit": 0,          // 字节内起始位（LSB=0）
          "bit_length": 32,        // 位长
          "byte_order": "big",     // "big" 或 "little"
          "signed": false,         // 整数是否有符号
          "is_float": true,        // 是否 IEEE-754 浮点
          "scale": 1.0,            // 缩放
          "offset": 0.0,           // 偏移
          "unit": "N"              // 单位
        }
      ]
    }
  ]
}
```

### 绘图布局 JSON

```jsonc
{
  "window_sec": 10.0,              // 时间窗口（秒）
  "auto_scroll": true,             // 自动滚动
  "panes": [                       // 窗格列表（顺序即从上到下）
    {
      "signals": ["FT_Sensor.Fx", "FT_Sensor.Fy", "FT_Sensor.Fz"],
      // colors 可选：信号名 -> 十六进制颜色；省略则自动配色
      "colors": {"FT_Sensor.Fx": "#d62728", "FT_Sensor.Fy": "#2ca02c", "FT_Sensor.Fz": "#1f77b4"}
    },
    {"signals": ["FT_Sensor.Mx", "FT_Sensor.My", "FT_Sensor.Mz"]}
  ]
}
```

## 随附示例

位于 `gui/signal_plot/protocols/`：

| 文件 | 内容 |
|---|---|
| `force_torque_sensor.json` | 六维力/力矩传感器协议：`Fx Fy Fz Mx My Mz`，各为大端 IEEE-754 单精度浮点（float32），共 24 字节，单位 N / NM。 |
| `force_torque_layout.json` | 配套布局：两张曲线图，分别画三个力分量与三个力矩分量。 |

使用：打开绘图窗口 → 导入协议选 `force_torque_sensor.json` → 导入布局选 `force_torque_layout.json`
→ 数据源选你的通道 → 连接设备后即可看到实时曲线。

> 示例里的 `can_id` 与字节序请按你的实际传感器核对：
> 改 ID 在编辑器里双击报文即可；若传感器是小端，把各信号 `byte_order` 改为 `"little"`。
> 24 字节超过经典 CAN 的 8 字节，必须用 **CAN FD** 模式连接。

## 常见问题

- **文件对话框打不开/卡住**：窗口内的导入导出已强制使用 Qt 自带（非原生）对话框，规避了
  Linux/WSL 上原生文件对话框卡死的问题。若主窗口「保存数据」也卡，可反馈一并处理。
- **曲线没数据**：确认①主窗口已连接且对应通道有报文；②协议里报文 ID / 帧类型与实际一致；
  ③数据源下拉选对了通道；④曲线图窗格已「选择信号」。
- **数值明显不对**：多半是**字节序**或**数据类型**填反了（大端↔小端、整数↔浮点），
  或缩放/偏移不对。
- **24 字节报文收不到**：经典 CAN 上限 8 字节，需用 CAN FD 模式连接。
